# Plan de implementación: Bloque de pruebas

> **Para agentes:** sub-skill obligatoria: superpowers:subagent-driven-development (recomendada) o superpowers:executing-plans. Los pasos usan casillas (`- [ ]`) para el seguimiento.

**Objetivo:** tener tests unitarios, de integración y end-to-end que se ejecuten solos en cada PR, sin tocar la base de Neon.

**Arquitectura:** PostgreSQL con pgvector en Docker (`compose.yaml`, puerto 5433). Vitest y Supertest en el backend, Vitest en el frontend, Playwright en `e2e/`, y un workflow de GitHub Actions con tres trabajos. El trabajo va en cuatro ramas, cada una con su PR.

**Stack:** Vitest, Supertest, jsdom, Playwright (Chromium), Docker Compose y GitHub Actions. Express 5, Prisma 7 y Next.js 16 ya existen.

**Especificación:** [docs/disenos/2026-10-30-pruebas-design.md](../disenos/2026-10-30-pruebas-design.md)

## Restricciones globales

- Git lo hace Jose: no hay pasos de commit. Cada rama sale de `origin/develop` con `--no-track`, y la siguiente se crea cuando la anterior está integrada.
- Código sin comentarios, igual en los tests. Nombres de los tests en español: `test("crear un Nodex sin título da 400")`.
- Base de pruebas: `postgresql://nodex:nodex@localhost:5433/nodex_test`. Imagen `pgvector/pgvector:pg17`.
- Ningún test ni script de pruebas puede conectarse a un host que no sea `localhost` o `127.0.0.1`.
- Los tests no tocan el código de la aplicación salvo para exportar `authLimiter`, `demoLimiter` y `refreshLimiter`.
- Si un test descubre un fallo de la aplicación: se marca con `test.fails` y un enlace a la línea, se anota en el registro y se le cuenta a Jose. No se arregla en estas ramas.
- Versiones: las que instale `npm install -D` en el momento. Quedan fijadas en `package-lock.json`.
- Node 24 en CI, como en local.

## Puntos de revisión

1. **Ejecutar los tests con el `.env` de Neon cargado:** el `globalSetup` debe pararlo antes de migrar nada. Se prueba en la Tarea 1.
2. **Memoria:** cada proceso de Vitest que carga la IA ocupa unos 600 MB. Con muchos en paralelo, el PC o la CI se quedan sin memoria. `maxWorkers: 2` en el backend (Tarea 1); se comprueba en la Tarea 6.
3. **Tests que dependen del orden:** cada test crea sus propios datos. Se comprueba una vez con `--sequence.shuffle` (Tarea 6).
4. **Recorridos end-to-end inestables:** crear la demo tarda hasta 10 s. Se espera con las aserciones de Playwright que reintentan solas, nunca con pausas fijas (Tareas 8 y 9).
5. **CI sin el modelo de IA:** si la descarga de Hugging Face falla, falla todo el trabajo. Se cachea `.cache/models` y la guía explica cómo volver a lanzarlo (Tarea 3).
