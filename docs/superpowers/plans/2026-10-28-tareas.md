# Interfaz de tareas: plan de implementación

> **Para agentes:** sub-skill obligatoria: superpowers:subagent-driven-development (recomendada) o superpowers:executing-plans. Los pasos usan casillas (`- [ ]`) para el seguimiento.

**Objetivo:** dar interfaz a la personalidad *tarea* (HU-12): sección "Tarea" en la ventana del Nodex y página `/tareas` con tablero arrastrable y calendario de mes.

**Arquitectura:** el backend no cambia (`/api/tasks`; cada Nodex trae `task`). La tarea se guarda dentro de las mutaciones que ya existen para crear y editar un Nodex, así la ventana sigue teniendo un único guardado y un único manejo de errores. El tablero usa dnd-kit con un estado local de columnas para la actualización optimista. El calendario es una rejilla CSS sin librería.

**Stack:** Next.js 16 (App Router), React 19, TanStack Query 5, Tailwind 4, shadcn/Radix y dnd-kit.

**Especificación:** `docs/superpowers/specs/2026-10-28-tareas-design.md`

## Restricciones globales

- Sin comentarios en el código. Los textos de la interfaz, en español.
- Las cargas se señalan con `<Spinner />`, nunca con esqueletos.
- Versiones fijas: `@dnd-kit/core@6.3.1`, `@dnd-kit/sortable@10.0.0`, `@dnd-kit/utilities@3.2.2`.
- Estados: `todo` → "Pendiente", `doing` → "En curso", `done` → "Hecha".
- Fecha límite: `<input type="date">`. Se envía como `new Date(\`${value}T00:00\`).toISOString()`. Para leerla y para agrupar por día se usa `toLocaleDateString("sv-SE")`, que da `AAAA-MM-DD` en hora local.
- Lo que dependa de la URL va dentro de `<Suspense>` (Next 16).
- Claude no hace commits: cada tarea termina con `tsc`, `eslint` y la comprobación en el navegador, y los cambios quedan sin commitear para Jose.
- Comprobación de cada tarea: `cd frontend && npx tsc --noEmit && npx eslint src`, sin errores.

## Puntos de revisión

1. **Clic contra arrastre:** un clic en una tarjeta del tablero abre el Nodex, no inicia un arrastre (sensor de puntero con `distance: 5`).
2. **Zona horaria:** una tarea con fecha 3 de noviembre aparece el día 3 en el calendario, en la tarjeta y al reabrir la ventana, sin desplazarse un día.
3. **Columna vacía:** se puede soltar una tarea en una columna sin tareas.
4. **Fallo al mover:** si `POST /move` falla, el tablero vuelve a los datos del servidor y sale un aviso con el error.
5. **Guardado de la ventana:**
   - Crear un Nodex con la tarea activada y con duplicados detectados guarda la tarea igualmente.
   - Desactivar la tarea en un Nodex que nunca la tuvo no llama a `DELETE`.

### Tarea 1: tipos, consultas y dependencias

**Archivos:**
- Modificar: `frontend/package.json` (las tres dependencias de dnd-kit)
- Modificar: `frontend/src/lib/types.ts`
- Crear: `frontend/src/lib/queries/tasks.ts`
- Modificar: `frontend/src/lib/queries/nodexs.ts` (`useInvalidateNodexs`, `useCreateNodex`, `useUpdateNodex`)
- Modificar: `frontend/src/lib/format.ts` (`TASK_STATUS_LABELS`, `toDateInput`, `fromDateInput`)

**Interfaces que produce:**
- `type TaskStatus = "todo" | "doing" | "done"`
- `type Task = { status: TaskStatus; dueAt: string | null; completedAt: string | null }`
- `Nodex.task: Task | null`
- `type TaskCard = Task & { nodex: { id: string; title: string; type: Nodex["type"]; url: string | null; priority: Priority | null } }`
- `type TaskInput = { status: TaskStatus; dueAt: string | null }`
- `TASK_STATUS_LABELS: Record<TaskStatus, string>`
- `toDateInput(iso: string): string` devuelve `AAAA-MM-DD` local.
- `fromDateInput(value: string): string` devuelve un ISO de las 00:00 locales.
- `useTaskBoard()`: clave `["tasks","board"]`, devuelve `Record<TaskStatus, TaskCard[]>` (el campo `columns` de `GET /tasks/board`).
- `useTaskCalendar(from: Date, to: Date)`: clave `["tasks","calendar",from.toISOString()]`, devuelve `TaskCard[]`.
- `useMoveTask()`: `mutate({ nodexId, status, index })` → `POST /tasks/:nodexId/move`; invalida `["tasks"]` en `onSettled` y muestra un toast de error en `onError`.
- `useCreateNodex`: la entrada acepta además `task?: TaskInput`. Si viene, tras el `POST /nodexs` hace `PUT /tasks/:id`.
- `useUpdateNodex`: la entrada acepta además `task?: TaskInput | null`. `undefined` no hace nada, `null` hace `DELETE /tasks/:id` y un objeto hace `PUT /tasks/:id`.
- `useInvalidateNodexs` también invalida `["tasks"]`.

**Produce:** `TaskCalendar({ onOpen }: { onOpen: (id: string) => void })`, que gestiona su propio mes.

  - Los días de otro mes, atenuados. Hoy, con un anillo `ring-primary`.
  - Las tareas se agrupan por `toDateInput(dueAt)` y se pintan como `TaskCardView compact`: gris si `todo`, `bg-primary` si `doing`, tachada si `done`.
- [ ] **Paso 3:** móvil (`md:hidden`): una lista de los días del mes que tienen tareas, con el encabezado "lunes, 3 de noviembre" y sus tareas. Si no hay ninguna, "No hay tareas con fecha este mes".
